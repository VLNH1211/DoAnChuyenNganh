Phiên bản đối chứng cơ sở: Cố ý thiếu các cơ chế kiểm soát bảo mật để minh chứng sự tồn tại của lỗ hổng Xác thực, Vượt quyền, BOLA/IDOR, SQL Injection, Token Replay, Lỗi Logic & Webshell Upload.

🎯 4 Kịch Bản Lỗ Hổng Cốt Lõi KB1–KB4 (Khớp 100% Đề Cương Nghiên Cứu)
Mô phỏng 4 điểm yếu cơ sở: Không cần token vẫn xem đơn (200), Người dùng thường gọi API Admin (200), IDOR xem trộm đơn (200) và SQL Injection bypass/dump dữ liệu (200).
KỊCH BẢN 1 (MT1) Kết quả: 200 OK
Chưa đăng nhập gọi API
Gửi yêu cầu GET không kèm JWT Token. Bản V1 trả về 200 OK kèm toàn bộ dữ liệu do thiếu [Authorize].
GET /api/orders
KỊCH BẢN 2 (MT2) Kết quả: 200 OK
Người dùng gọi API Admin
Dùng tài khoản thường (userA) gọi API Quản trị. Bản V1 thiếu Role check, làm lộ mật khẩu plaintext và danh sách user.
GET /api/admin/users
KỊCH BẢN 3 (MT3) Kết quả: 200 OK
Khai thác BOLA / IDOR
userA đổi ID sang đơn #3 của userB. Bản V1 không kiểm tra UserId chủ sở hữu, trả về 200 OK xem trộm đơn hàng.
GET /api/orders/3
KỊCH BẢN 4 (MT4) Kết quả: 200 OK
Tấn công SQL Injection
Gửi payload '?keyword=' OR 1=1 --'. Bản V1 ghép chuỗi thô, trả về 200 OK dump toàn bộ CSDL hoặc lộ mã lỗi 500.
GET /api/orders/search?keyword=...
⚡ Kịch Bản Điểm Yếu Mở Rộng KB5–KB8 (Token Replay, Business Logic Flaw, Insecure File Upload, No Rate Limit)
Mô phỏng các nguy cơ an ninh mở rộng trên V1: Không thu hồi token sau logout, Cho phép số tiền âm & Mass Assignment, Upload Webshell thành công và Không giới hạn tần suất gọi API.
KB5 (TOKEN REPLAY) Kết quả: 200 OK
Không Thu Hồi Token (Replay)
Đăng xuất (POST /api/auth/logout), sau đó dùng lại token cũ gọi /api/auth/me. V1 không có Blacklist nên token cũ vẫn hợp lệ (200 OK).
POST /logout -> GET /me
KB6 (LOGIC & IDOR) Kết quả: 200 OK
Logic Nghiệp Vụ & IDOR Sửa/Xóa
Tạo đơn tiền âm (-999k) hoặc userA xóa đơn #3 của userB. V1 chấp nhận số tiền âm (200 OK) và cho phép xóa đơn của người khác.
POST /orders | DELETE /orders/3
KB7 (FILE UPLOAD) Kết quả: 200 OK
Upload Webshell / Extension Lạ
Gửi file 'webshell.jpg.aspx' hoặc script text. V1 không kiểm tra Magic Bytes, chấp nhận tải lên (200 OK), nguy cơ RCE.
POST /api/orders/1/upload
KB8 (NO RATE LIMIT) Kết quả: 200 OK
Không Giới Hạn Tần Suất (Spam)
Spam liên tục 8 requests vào /api/orders/rate-test. V1 không có Rate Limiting, xử lý toàn bộ 8 request thành công (200 OK).
GET /api/orders/rate-test (Spam)
