🎯 4 Kịch Bản Bảo Mật Cốt Lõi KB1–KB4 (Khớp 100% Đề Cương Nghiên Cứu)
Mô phỏng 4 mục tiêu bảo mật căn bản: Xác thực JWT (401), Phân quyền RBAC (403), Kiểm soát BOLA/IDOR (403) và Lọc SQL Injection (400).
KỊCH BẢN 1 (MT1) Mã chặn: 401
Chưa đăng nhập gọi API
Gửi yêu cầu GET không kèm JWT Token. Bản V2 chặn đứng với mã 401 Unauthorized và ghi Audit Log.
GET /api/orders
KỊCH BẢN 2 (MT2) Mã chặn: 403
Người dùng gọi API Admin
Dùng tài khoản thường (userA) gọi API Quản trị. Bản V2 kiểm tra Policy AdminOnly và chặn với mã 403 Forbidden.
GET /api/admin/users
KỊCH BẢN 3 (MT3) Mã chặn: 403
Khai thác BOLA / IDOR
userA đổi ID sang đơn #3 của userB. Bản V2 đối chiếu UserId trong Token và chặn với mã 403 Forbidden, không lộ dữ liệu.
GET /api/orders/3
KỊCH BẢN 4 (MT4) Mã chặn: 400
Tấn công SQL Injection
Gửi payload '?keyword=' OR 1=1 --'. Bản V2 áp dụng Input Validation & Parameterized Query chặn 400 Bad Request, không lỗi 500.
GET /api/orders/search?keyword=...
⚡ Kịch Bản Bảo Mật Mở Rộng KB5–KB8 (Defense-in-Depth: Token Replay, Business Logic, Magic-Bytes, Rate Limiting 429)
Nâng cao năng lực phòng thủ: Quản lý vòng đời JWT (JTI Revocation), Chống lỗi Logic & Mass Assignment, Kiểm tra chữ ký byte tệp thực tế và Phòng chống Brute-force/Spam API.
KB5 (REVOCATION) Mã chặn: 401
Thu Hồi Token Khi Đăng Xuất
userA đăng xuất (POST /api/auth/logout), sau đó kẻ tấn công lấy lại JWT cũ gọi /api/auth/me. V2 kiểm tra JTI Blacklist chặn 401 Unauthorized.
POST /logout -> GET /me
KB6 (LOGIC & IDOR) Chặn: 400 / 403
Business Logic & IDOR Sửa/Xóa
Tạo đơn tiền âm (-999k) hoặc userA cố xóa đơn #3 của userB. V2 chặn 400 Bad Request (tiền âm) & 403 Forbidden (IDOR khi xóa).
POST /orders | DELETE /orders/3
KB7 (MAGIC BYTES) Mã chặn: 415 / 400
Upload Webshell Giả Mạo Ảnh
Gửi file 'webshell.jpg.aspx' hoặc file .jpg chứa script text. V2 kiểm tra Magic Bytes (FF D8 FF) chặn 415/400, chống RCE.
POST /api/orders/1/upload
KB8 (RATE LIMITING) Mã chặn: 429
Chống Spam API / Brute-force
Spam liên tục 8 requests vào /api/orders/rate-test. V2 giới hạn 5 req/5s, trả về 429 Too Many Requests kèm Retry-After.
GET /api/orders/rate-test (Spam)

Bảng Kiểm Tra HTTP Security Headers Chuẩn OWASP
Bản V2 tự động gắn đầy đủ các Header an ninh để phòng thủ chống Clickjacking, MIME-Sniffing và XSS, đạt điểm tối đa trên OWASP ZAP.
Tên HTTP Header Ý Nghĩa Bảo Mật (Mục Đích) Giá Trị Trên V1 (Baseline) Giá Trị Trên V2 (Hardened) Trạng Thái
X-Content-Type-Options Chống MIME-sniffing, buộc trình duyệt tuân thủ MIME type Không có (Thiếu) nosniff ✓ Chuẩn OWASP
X-Frame-Options Chống tấn công Clickjacking / Chèn iframe trái phép Không có (Thiếu) DENY ✓ Chuẩn OWASP
X-XSS-Protection Kích hoạt bộ lọc XSS Filter của trình duyệt Không có (Thiếu) 1; mode=block ✓ Chuẩn OWASP
Referrer-Policy Bảo vệ quyền riêng tư đường dẫn nguồn gốc URL Không có (Thiếu) strict-origin-when-cross-origin ✓ Chuẩn OWASP
Content-Security-Policy Giới hạn nguồn nạp tài nguyên an toàn (CSP) Không có (Thiếu) default-src 'self' 'unsafe-inline' data:; ✓ Chuẩn OWASP
